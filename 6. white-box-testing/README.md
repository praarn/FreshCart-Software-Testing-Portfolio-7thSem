# 08 - White-Box Testing

Unit tests with branch coverage on the backend business logic, plus control flow graphs and
basis path analysis for three functions.

## The two white-box methods

| Method | What it does here | Artifacts | Test cases |
|---|---|---|---|
| 1. Basis path testing | Control flow graph, V(G) three ways, one test per independent path, for three functions | [`Control_Flow_Graphs/`](Control_Flow_Graphs/), [`Basis_Path_Testing.md`](Basis_Path_Testing.md) | `TC-M4-022` (`validate_coupon`, 10 paths), `TC-M5-028` (`_validate_payment`, 7 paths), `TC-M6-020` (`complete_delivery`, 6 feasible of 7) |
| 2. Statement, branch and condition coverage | Unit tests chosen to drive each statement, decision and condition both ways, then measured with coverage.py | [`Coverage_Report.md`](Coverage_Report.md), `coverage_html/` | `TC-M4-023`, `TC-M5-029`, `TC-M6-021`, `TC-M1-038`, plus `TC-M1-039` (review of the validation regexes, DEF-005) |

Both methods run from the same unit tests in `0. application/backend/tests/unit/`; the first picks the inputs from
the graph, the second checks what those and all other tests actually executed. The black-box counterpart (equivalence
partitioning and boundary value analysis, run against the live API) is in
[`../5. black-box-testing/`](../5.%20black-box-testing/README.md).

## Contents

session and in CI.

## Why these targets

| Function | Rule | Reason |
|---|---|---|
| `pricing_service.validate_coupon`, `compute_discount`, `compute_delivery_fee` | R4.1-R4.4 | Money logic. 9 predicates in one function, each producing its own error message. |
| `checkout_service._validate_payment`, `_luhn_ok`, `_validate_slot`, `_validate_address` | R5.1-R5.3 | Three payment methods, a checksum, and date arithmetic with several boundaries. |
| `order_service.admin_advance_status`, `complete_delivery`, `cancel_order`, `assign_delivery_partner` | R6.1-R6.4 | The order state machine and OTP lockout. |
| `auth_service.authenticate_user`, `core/security` | R1.5 | Lockout counter, 15-minute expiry, token expiry (found DEF-003). |

Not targeted: routers (thin wrappers, covered by the API suite), `cart_service`,
`catalog_service`, `admin_service`, `banner_service`, `wishlist_service` (mostly SQL queries;
their rules are covered by the API and Selenium suites).

## Reproduce

```bash
cd "0. application/backend"
pip install -r requirements.txt
pytest --cov=app --cov-branch --cov-report=term-missing --cov-report=html:"../../6. white-box-testing/coverage_html"
```

Database-backed tests use an in-memory SQLite engine created per test (`tests/unit/conftest.py`);
they never touch `data/freshcart.db`.
